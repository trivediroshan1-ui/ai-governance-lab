# Contributing

The most useful thing you can add is a case I did not think of.

1. **Write your expected result first**, before you read the code. That is the rule every case in this lab follows.
2. **Use made-up data only.** No real people, credentials, companies or employer information.
3. **Open an issue** with the *Propose a test case* form.
4. If it fits, it goes into the next round with your name on it, and the guesses file is hashed and committed before the code, as for every round.

Code changes are welcome too. Keep them small, run `python3 run.py --dry-run` before opening a pull request, and say what you expect the change to do to the results.
